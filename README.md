# StreamStats
Потоковый анализатор файлов форматов CSV и JSONL. Программа проверяет события без полной загрузки в оперативную память и формирует JSON-отчет со статистикой.

## 🛠️ Возможности
- Чтение CSV-файлов с заголовками и JSONL-файлов построчно.
- Проверка временной метки, уровня события, источника и сообщения.
- Поддержка уровней `DEBUG`, `INFO`, `WARNING`, `ERROR` и `CRITICAL`.
- Подсчёт событий по уровням и источникам.
- Подсчёт событий ERROR и CRITICAL по источникам и формирование топ-5.
- Определение первой и последней временных меток.
- Обработка нескольких входных файлов за один запуск.
- Формирование JSON-отчёта с сохранением кириллицы.
- Режим **--skip-invalid** для пропуска некорректных записей.

## ⚙️ Требования
Python 3.10 или новее.

## 📥 Установка
### Для macOS/Linux:

#### 1. Создайте и активируйте виртуальное окружение. Скачайте проект:
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```
После этого начало командной строки терминала должно выглядеть примерно так:
```
(.venv) user@MacBook-Air lab_02 %
```


#### 2. Проверьте, что окружение активировалось корректно:
```bash
which python
```
Путь должен оканчиваться примерно так:
```bash
.../lab_02/.venv/bin/python
```
**✅ Программа готова к использованию!**

### Для Windows:
- На этапе активации виртуального окружения вместо команды `source .venv/bin/activate` напишите:
```
.venv\Scripts\Activate.ps1
```

## 🧑‍💻 Использование
### Вывести справку со списком команд:
```
python -m streamstats --help
```
### Анализ одного CSV-файла с сохранением отчёта:
```
python -m streamstats analyze test_data/events.csv --format csv --output report.json
``` 
### Анализ JSONL с пропуском некорректных записей:
```
python -m streamstats analyze test_data/events.jsonl --format jsonl --skip-invalid
```
> **Если --output не указан, JSON-отчёт выводится в консоль.**

#### 💡 Можно передать несколько файлов одного формата:
```
python -m streamstats analyze test_data/events.csv test_data/events_part2.csv --format csv
```

- По умолчанию при некорректной записи обработка прекращается, выводится сообщение с именем файла и номером строки, программа завершает работу с кодом 2. С `--skip-invalid` запись пропускается, в лог выводится предупреждение `WARNING`, а количество пропусков сохраняется в поле `skipped` отчёта.

## 📊 Поля отчёта
- `total` — число корректных событий.
- `levels` — количество событий каждого уровня.
- `by_source` — количество событий и ошибок по источникам.
- `top_error_sources` — топ-5 источников по числу событий `ERROR` и `CRITICAL`.
- `first_timestamp` и `last_timestamp` — временные границы входных событий либо `null`, если событий нет.
- `skipped` — число пропущенных некорректных записей.
